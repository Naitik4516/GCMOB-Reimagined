# AGENTS.md

Single-package Flutter app: **gCMOB Reimagined** — a CCTV viewer for Dahua/CP Plus DVR/NVRs over RTSP. Not a monorepo; everything lives under one `pubspec.yaml`.

## Commands

- `flutter pub get` — after any `pubspec.yaml` change
- `flutter analyze` — the lint **and** typecheck gate (no separate typecheck step). Currently passes with 0 issues; keep it that way.
- `flutter test` — runs all tests under `test/` (`widget_test.dart` for RTSP helpers/app boot, `grid_cubit_test.dart` for paging/order/restore/focus, `tile_shortcuts_test.dart` for key mapping, `tile_cubit_test.dart` for connect/retry/watchdog policy, `live_controls_test.dart` for the shared live row, `app_chrome_test.dart` for system-UI resolution, `profile_list_edit_test.dart` for the edit sheet, `profile_form_test.dart` for save-time validation/probing, `rtsp_probe_test.dart` against a fake RTSP server, plus `profile_store_test.dart` and `profiles_cubit_test.dart` for storage). Shared fakes/harnesses live in `test/helpers/` (`FakeTilePlayer`, `FakeSecureStorage`, `FakeProfileStore`, `FakeGridStore`, `testGrid`).
  - single test: `flutter test --plain-name "GridCubit pages"` (substring match on the test name)
- `flutter test --coverage` — writes `coverage/lcov.info` (already gitignored); summarize with `lcov --summary coverage/lcov.info` when lcov is installed. There is no coverage threshold and no CI enforcement.
- `flutter run -d <device-id>` — no dev server; run on a device/emulator
- `flutter build apk --release` — requires a gitignored `android/key.properties`; the build fails by design without it. Release also needs `INTERNET` in `android/app/src/main/AndroidManifest.xml` (the debug/profile manifests are not merged into release).
- **Do not run `dart format` across the repo unless explicitly asked.** The code predates the current tall-style formatter: `dart format lib test` rewrites 12 of 19 files. Match surrounding style by hand instead.

Verification order: `flutter analyze` → `flutter test`.

`analysis_options.yaml` excludes `build/`, `android/`, `windows/`, `linux/`, so `flutter analyze` only checks `lib/` and `test/`.

## Architecture

- Entry: `lib/main.dart` → `MediaKit.ensureInitialized()` **must** run before `runApp` (media_kit native libs) → `lib/app/app.dart` (`CctvApp`, a plain `MaterialApp`).
- Feature-first layout, each feature self-contained as `ui/` + `bloc/` + `data/` + `models/`:
  - `lib/features/profiles/` — DVR profile list/form, persistence, home screen
  - `lib/features/live/` — live grid, tiles, fullscreen player
  - `lib/core/` — `rtsp/` (URL builder, mpv options), `platform/` (`app_chrome.dart`, `app_fullscreen.dart`, `is_tv.dart`)
- State: `flutter_bloc` **Cubits** with `equatable` states — no Bloc classes, no router package, no DI container; navigation is raw `Navigator.push`.
- Player: `media_kit` + `media_kit_video`. `MediaKitRTSPController` (`features/live/player/`) owns one `Player` per tile and implements `TilePlayer`; `TileCubit` depends on that interface (plus an optional `VideoController` UI handle), so connect/retry logic is unit-testable without libmpv. Low-latency mpv properties are set through the native `player.platform.setProperty` **before** `Player.open()`.
- Targets: Android (+ Android TV / Fire TV), Linux, Windows. **No iOS/macOS/Web runners exist.**

## Conventions that bite

- **Passwords never live in `DvrProfile` or SharedPreferences.** `ProfileStore` (`features/profiles/data/profile_store.dart`) splits storage: non-secrets in SharedPreferences (`dvr_profiles_v1`), passwords in `flutter_secure_storage` under `dvr_pass_<id>`. Saving writes the password before the profile JSON; corrupt records are skipped on load; changing a profile's channel count or deleting it clears `ch_order_<id>`.
- **Saving a profile validates the connection first.** `RtspProbe` (`core/rtsp/rtsp_probe.dart`) sends the same `DESCRIBE` for channel 1's sub-stream that libmpv would (Basic, then a Digest/MD5 retry when challenged) over a raw socket, so bad IP/port/credentials fail fast without spawning a player. Creation always probes; edits probe only when host/port/username/password changed, so renaming works offline. Failure shows a "Fix it / Save anyway" dialog — never a silent save. `ProfileFormPage.probe`/`store` are injectable for tests; the probe never puts credentials in its messages.
- **RTSP indexing** (`lib/core/rtsp/rtsp_url.dart`): UI channels are 1-based, the Dahua `channel=` query param is 0-based; `subtype=1` = sub-stream (grid tiles, muted), `subtype=0` = main stream (fullscreen, audio on).
- **The grid never scrolls** — tile aspect ratio is derived from the viewport in `camera_grid_widget.dart`. Don't add scrolling or fixed aspect ratios.
- **Failure policy:** a failed tile keeps its slot and shows a retry overlay — stream health never reorders the grid (no sinking; `GridCubit` has no failure API). Retry is strictly user-initiated (`TileCubit.retry()`); the first retry opens immediately, later ones back off 2–10s, and a successful playback resets the counter. `routeTileFailure` only reacts while a channel is focused (`GridState.isFocused`; a dead visible layer exits to grid). Don't add an automatic reconnect loop at the cubit level.
- **Frozen-feed watchdog:** a `playing` tile that makes no `position` progress for `stallTimeout` (default 20s, checked every 5s) fails with “Stream stopped responding — tap Retry”. Buffering gets one extra interval; loading/reconnecting is covered by `connectTimeout` instead. Position events must be ignored outside `playing`, and the timer must stop on `_fail`, retry, reconnect, suspend, and `close`.
- **Tile border:** the outline lives on an `IgnorePointer` overlay at the TOP of the tile Stack, never on the outer container — Container paints decoration under its child, so full-bleed video covers border corners. Outer container carries only glow shadow; stack is `ClipRRect`ed.
- **Phone body never remounts the grid:** `_PhoneBody` keeps one `CameraGridWidget` as child 0 in every mode; immersive layers append after it. Swapping body subtrees on rotation disposes every TileCubit (logcat MediaCodec teardown wave) and reloads all streams.
- **No reorder in 1x1:** nothing to swap with, and the drag wrapper would eat pinch/pan/tap gestures — bare `DragTarget`-less tile, grabs ignored, and the desktop right-click channel picker is disabled (`onPickChannel` is null when `reorder` is false).
- **Reshuffles must not recreate tiles:** `GridView.findChildIndexCallback` (`findTileIndex`) moves keyed tiles on reorder — without it every shifted tile (and its working stream) reconnects, avalanching one failure across the grid.
- **Position memory:** `GridCubit.restore()` loads the per-profile order (`ch_order_<profileId>`) and the global layout (`grid_size`) at startup; every `swapChannels`/`setGridSize` persists. Reorder happens only on explicit user action. Persistence is best-effort: a failing save never rolls back the visible order/layout, and a user change that lands while `restore()` is still reading wins.
- **TV / D-Pad:** the first list item is autofocused, tiles use `KeyboardListener` + focus glow (`CctvTheme.focusColor`); every interactive widget needs a focus path. `isTvCapable` is true for *all* Android builds (no Leanback check exists).
- **Single-camera view = focused 1x1, not a route.** `GridCubit.focusChannel` sets `focusedChannel` only; `layoutSize` and `page` stay untouched, so double-click / Esc / Back / Grid exit restores exactly the grid page the user left. `gridSize` is computed (1 while focused); the pager surfs the previous/next channel in `order` (no wrap) and labels use `displayPage`. `setGridSize` exits focus and resets the page. There is no fullscreen page (`wakelock_plus` removed).
- **Spotlight handoff (dual-layer):** the SD provider sits directly under the grid with a quality-independent key, so entering single view keeps the playing picture while a nested HD provider loads underneath and swaps on first HD frames (`Visibility` layers, focus follows the visible layer). Never nest providers differently per mode — ancestor changes remount and kill the stream. Shared `routeTileFailure` reads live grid state so moved-in cubits behave. **Once HD is primary, `_TileFrame` suspends the hidden SD player** (`TileCubit.suspend` → `TileConn.suspended`); exit focus, HD failure, and HD→SD toggle call `resume()`. Suspend only after HD first frames; `kSuspendSdUnderHd` in `camera_grid_widget.dart` is the rollback switch. Late teardown events are ignored while suspended.
- **First-frame gate:** `playing` is reported only after sized frames arrive (`stream.width > 0`) — `playing` alone precedes the first decoded frame and shows black. Same gate drives the fullscreen HD swap.
- **Load path (slow-stream fixes, do not regress):** load-critical mpv flags must be *awaited* before `open()` (`ensureFlags`, never fire-and-forget — otherwise tiles silently fall back to UDP); flags are applied once and one failed property is logged without disabling the rest. `reconnect=yes` stays OFF — recovery is user-initiated, and `_fail` stops the player so mpv cannot reconnect behind the overlay. Every `open()` goes through `RtspOpener` (max 3 concurrent handshakes, FIFO), and `MediaKitRTSPController.dispose()` waits for an in-flight open before disposing. Debug instrumentation is `MediaKitRTSPController.activePlayers` (instances) + `activeStreams` (open sessions) plus per-open `open`/`firstFrame` logs (never URLs); numbers live in `docs/performance.md`.
- **Tile open gesture:** double click / double tap opens the single view (single tap only focuses); TV OK still toggles directly when the tile owns primary focus. Tiles carry a mute button when HD (`TileState.muted`, M key toggles); the state only flips after `TilePlayer.setMuted` succeeds. Desktop drag-and-drop uses slop-based `Draggable` with grab/grabbing cursors — not long-press.
- **Tile hover:** `CameraTileWidget` flips a `ValueNotifier<bool>` from `MouseRegion` and only the drag-hint `ValueListenableBuilder` rebuilds. Never `setState` on enter/exit — that rebuilds `Video` + `InteractiveViewer` under every pointer sweep.
- **Shared live controls:** `LiveControls` (`features/live/ui/live_controls.dart`) is the single row used by the desktop title bar, phone bottom bar and landscape immersive bar. Differences are flags (`showShortcuts`, `showPager`, `showPageLabel`, `showGridExit`, `iconColor`), not copies. The pager only renders for `pageCount > 1` and uses `displayPage`; the grid-exit button only while `isFocused`. Do not re-declare the layout/quality segmented buttons elsewhere.
- **App fullscreen:** `AppFullscreen` (`core/platform/`) — borderless window on desktop (window_manager, choice persisted; min size 428×444), immersive bars on Android; F11 toggles from anywhere, plus a toggle button. Android system bars are owned by `AppChrome`: immersive when app fullscreen **or** the current page asks for it; `LivePage.dispose()` clears page immersion so popping from landscape restores bars.
- **Zoom mechanics:** `InteractiveViewer` (pinch/pan) + manual wheel-zoom matrix in `CameraTileWidget._onWheel` — the viewer maps wheel to pan, so the wheel needs its own handler. Uses non-deprecated `translateByDouble`/`scaleByDouble`.
- **Grid metrics:** roomy padding/gaps (20/14) past phone widths — desktop always, or viewport ≥700px — else compact 8/8. The aspect fit math must subtract the same pad/gap it renders with.
- **Zoom everywhere:** all tiles zoomable (wheel + pinch); a tile zoomed past 1x reports via `onZoomChanged` and the grid drops its reorder wrapper so drags pan instead. Immersive landscape uses long-press drag (fling turns pages) for the same reason.
- **App frame:** `AdaptiveShell` — Windows gets `DesktopTitleBar` (draggable, min/max/close; native bar hidden in `AppFullscreen.init`); Linux keeps its native KWin frame (theme rounding included) with a regular `AppBar` inside; mobile/TV use `AppBar` + bottom bar (`hideChrome` drops both for immersive landscape). Windows title bar carries layout + SD/HD + shortcuts + fullscreen; phones keep title + fullscreen only. Pager chevrons hide at the ends, never sit disabled.
- **Phone landscape immersion:** `LivePage` enters ultra-immersive (bars hidden, fling pages, tap reveals floating bar + back button, 5s auto-hide) only after portrait was seen once — landscape-locked TVs never enter. The floating bar carries layout + SD/HD + paging + grid-exit. Rotation immersion never touches the persisted fullscreen pref; phones launch non-fullscreen by default.
- **Seek-error tolerance:** media_kit forwards all mpv error-level logs, so benign live-stream notes (`isBenignLiveError`, any `seek` substring — including the standalone `--force-seekable` hint) never fail a tile — they rearm a 10s stall watchdog that fails only if mpv is still stuck buffering.
- **Weak-SoC grid bring-up:** tile first-starts stagger 250ms per slot (`TileCubit.startDelay`) on top of the 3-wide `RtspOpener` — nine simultaneous MediaCodec sessions overwhelm low-end phones.
- **Rounded window (Windows-only):** transparent backdrop (`setBackgroundColor`) + `ClipRRect` radius 12 around every route via `MaterialApp.builder`, flattened while app-fullscreen. `window_rounded_corners` is Android-only — irrelevant. Linux keeps native KWin decorations instead.
- **Shortcuts (tile focused):** mapping lives in `tile_shortcuts.dart`: `1/2/3` layout, `[`/`]` or PgUp/PgDn (also ChUp/ChDown) paging, `M` mute, `Esc` cancel grab / exit single view, `F1` help dialog. Confirm is ignored while an overlay button (Retry/mute) owns primary focus, and losing focus cancels an in-flight hold-grab. `F11` app-fullscreen goes through a global `HardwareKeyboard` handler in `CctvApp` — Focus-bubble handlers miss keys when nothing is focused, do not use them for global keys.

## Testing quirks

- **No mocks are registered.** `SharedPreferences` / `FlutterSecureStorage` throw `MissingPluginException` under `flutter test`. Tests that need storage must call `SharedPreferences.setMockInitialValues({})` first; `ProfileStore(secure: FakeSecureStorage(...))` accepts the shared keyring fake; `GridCubit` tests either inject `saveOrder` (`testGrid`) or use `FakeGridStore`, and still set mock prefs when exercising `restore()`.
- **Player tests use a fake, not libmpv.** `test/helpers/fake_tile_player.dart` implements `TilePlayer` and exposes `autoPlay`, `throwOnOpen`, `throwOnMute`, and event emitters; `tile_cubit_test.dart` drives timers with `fake_async` (`connectTimeout` 50ms). `TileCubit` also accepts an injectable `now` clock so the watchdog sees fake time. Close cancels stream subscriptions without awaiting their futures (they can complete outside the fake zone), then disposes the player.
- **The boot test is a real assertion.** `'App boots to an empty profile list'` sets mock prefs, waits for `ProfilesCubit.load()`, then asserts `find.byKey(const ValueKey('empty'))`, `ProfilesStatus.loaded`, and no profiles/error. Storage-failure behavior is covered directly in `profiles_cubit_test.dart`; don't boot the whole app with a broken plugin.
- Test files are feature-scoped (`grid_cubit_test.dart`, `tile_cubit_test.dart`, `profile_store_test.dart`, `profiles_cubit_test.dart`, `live_controls_test.dart`, `tile_shortcuts_test.dart`, `app_chrome_test.dart`, `widget_test.dart` for RTSP/app boot). Every shared fake lives under `test/helpers/`; suite conventions are in `test/helpers/README.md`.
- No `integration_test/` directory exists.
